# Contributing

Use a small, reviewable GitHub Flow. Agents or the audited repository creator handle the mechanical Git and GitHub delivery actions by default; users provide requirements, review Pull Requests, and explicitly approve or reject merges.

1. Record the problem or intended outcome in an Issue when the change needs shared context.
2. The responsible Agent creates a focused branch from the current default branch.
3. The Agent makes the smallest coherent change, runs the relevant repository checks, commits, and pushes the branch.
4. The Agent creates or updates a Pull Request with actual verification evidence, risks, and user-visible acceptance steps when applicable.
5. Keep internal checks separate from user acceptance.
6. The user reviews the Pull Request and explicitly approves or rejects the merge.
7. Merge only after the required independent review and explicit merge authorization.

Do not commit credentials, private customer data, production exports, or undocumented destructive migrations.

Repository-specific contribution guidance overrides this default when it is more specific.
